# 0.0.3 修复记录

用户反馈：正文已选中文字却不能划重点；主页、课程切换有约 1.5 秒迟滞。

## 修复前证据

[失败用例](https://github.com/wm0104/xinxin-yuwen-garden/actions/runs/39594956219) 完成编译后复现三个问题：

- 真实长按正文后找不到可用的“划重点”操作。
- AppStore 连续 100 次读取未变课表耗时 1057.6 ms，超过 100 ms 的重复读取预算。
- 视频 URL 没有官方外链播放器要求的分集参数 `p`，原代码错误地使用 `page`。

另一次 Linux 基准中，原主页展开课表并逐条格式化日期的表达式连续执行 10 次耗时约 750 ms。它是重复工作负担的证据，不是 XR 切页延迟的实测值。

## 改动

- 正文底部增加常驻“划重点”。通过实际 UITextView 选区启用，点击后保存摘录并持久化高亮；已有笔记不覆盖。仍可另外编辑备注。
- 文本及高亮未变化时，不重新设置 attributedText；仅内容、字号或宽度变化时重新测量高度，避免选区被无关刷新打断。
- 课次只在课程、调课或学期变化，以及恢复备份后重建；主页与课表按日期读取索引。页签选择放在根视图本地状态，不广播给整个资料仓库。
- 合集分集参数改为官方要求的 `p`，保留时间点参数 `t`。

自动回归同时检查正文真实选词、保存、重启保留，以及调课与撤销后的缓存一致性。最终结果以对应提交的 Actions 运行记录为准。

## 边界

没有声称 XR 真机迟滞已降到某个毫秒数，仍需覆盖安装后复测。视频目前仍是 B 站官方网页播放器；此补丁只修正分集，不宣称已完成高清系统播放器。Bark 定时服务依旧等待配置。
